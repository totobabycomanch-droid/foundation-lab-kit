# Chapter 11 workspace 규칙

- [연결 명세](../connection_spec.md)와 [Chapter 지침](../AGENTS.md)을 먼저 읽는다.
- 백엔드는 `erp-project/`, 화면은 `frontend-project/`에서 구현한다.
- 기능 구현 요청에는 SQL·API·화면을 연결하고 자동 검사까지 진행한다. 화면 테스트용 서버 실행·종료는 독자가 직접 하며, 검사에 필요한 임시 서버는 검사 후 종료한다. 층마다 독자의 추가 요청을 기다리지 않는다.
- 실제 `.env`를 열거나 출력하지 않는다. 실행 도구·서버가 로컬 설정을 내부적으로 사용해 연결하는 것은 허용한다.
- DB 쓰기는 전용 대상 대조와 ch11 표식 확인 뒤 수행한다. 최초 표식 준비 조건은 연결 명세를 따른다.
- 정상 A·부족 B는 서로 다른 상품을 사용하고 자동 검사 데이터와 분리한다.
- 기존 개인 코드·DB 결과는 보존한다. 명세 충돌이나 예상 밖 객체를 발견하면 덮어쓰거나 전체 초기화하지 않는다.
- 독자가 전용 DB의 완전 초기화를 명시한 경우는 상위 ch11 지침의 예외를 따른다. 제공 명령의 지정 객체 삭제만 허용하며 로컬 코드·설정은 지우지 않는다.
- 독자 직접 확인은 정상·부족 두 사례다. 기존 다섯 관찰 절이나 DB·API별 반복 승인을 필수로 요구하지 않는다.
- 관찰값은 독자가 작성한다. 코드 존재·자동 검사·독자 실행을 구분한다.
- 문제 수정 후 관련 검사를 재실행하고 필요한 사례만 다시 준비한다.
- 결과 설명은 요청 전송·조건 검사와 함께 저장·저장 후 재조회의 실제 코드 세 곳을 중심으로 한다.
- 미실행 DB·HTTP·브라우저 검사는 `Not Run`으로 보고한다. 빌드 성공을 화면 동작 검증으로 대신하지 않는다.
