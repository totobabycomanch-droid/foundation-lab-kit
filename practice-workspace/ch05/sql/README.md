# Chapter 5 SQL 실행과 필수 검사

## 실행 단위

이 폴더에 AI가 생성한 01_current_and_history.sql과 02_relationship_and_delete.sql을
각각 기초 실습 전용 Supabase SQL Editor에서 실행합니다. Python·HTTP 서버·Auth 사용자 준비는 없습니다.

파일마다 BEGIN부터 COMMIT까지 전체를 실행합니다. 일부 구문만 선택하지 않습니다.
CREATE TEMP TABLE과 ON COMMIT DROP으로 매 실행의 준비와 정리를 묶습니다.
두 파일은 서로의 테이블이나 이전 실행 결과에 의존하지 않습니다.

예상하지 못한 오류가 발생하면 원인을 확인합니다. 실패한 트랜잭션이 남아 있다면 ROLLBACK을
실행해 취소한 뒤 수정한 파일 전체를 다시 실행합니다. 영구 테이블 삭제로 복구하지 않습니다.

## 실습 1 — 현재값과 이력

- 상품 A001의 현재 수량을 10에서 7로 변경한다.
- 별도 이력에는 입고 10과 출고 -3, 사유를 두 행으로 남긴다.
- 실제 조회값으로 현재 수량 7, 이력 합계 7과 두 이력 행의 수량을 각각 검사한다.
- 현재값을 갱신하는 것 자체가 잘못이라고 설명하지 않는다. 현재값만으로 변경 이유를 설명할 수
  없다는 차이를 보여 준다.

## 실습 2 — 상품과 거래 관계

- 상품 A001 한 행과 그 상품을 참조하는 양의 수량의 거래 한 행을 만든다.
- 상품을 참조하는 외래 키는 거래가 있는 상품의 물리 삭제를 막도록 설정한다.
- 실제 DELETE를 시도하고 foreign_key_violation이 발생했는지 검사한다. 예상된 오류는 처리하되
  오류가 나지 않았거나 다른 오류가 발생한 경우 성공으로 처리하지 않는다.
- 상품의 is_deleted 표시를 변경한다. 목록은 제외 표시가 없는 상품만 조회한다.
- 실제 조회로 목록 0건, 전체 상품 1건, 거래 1건을 확인한다.
- JOIN 결과로 기존 거래번호·상품코드·상품명·수량과 제외 표시가 보존됐는지 검사한다.
- 삭제 차단 확인값도 실제 시도에서 얻어 결과에 표시한다.
- 상품 연결과 당시 값 보존은 구분한다. JOIN으로 가져오는 상품명은 현재 상품명이며,
  당시 상품명·단가를 보존하려면 거래 기록에 별도로 남겨야 한다. 이 예제에 추가 실습은 만들지 않는다.

## 검증 근거

각 파일에 결과가 다르면 RAISE EXCEPTION으로 실패하는 검사를 포함합니다.
예상 숫자만 출력하거나 오류 문구만 출력해서 통과로 보고하지 않습니다.
각 파일의 마지막 조회에서 핵심 결과를 한 표에 모아 보여 줍니다. 실습 1은 현재값·이력 두 행의
내용·행 수·합계, 실습 2는 삭제 차단 여부·목록 건수·상품과 거래 건수·연결된 거래 값을 포함합니다.
독자는 파일별로 이 표 하나를 복사해 AI 검증 요청에 붙입니다.
각 파일 전체를 두 번 실행해 같은 조회 결과가 나오는지 확인합니다. 독자는 결과 표와 함께
파일별 전체 재실행 여부와 결과 일치 여부를 알려 줍니다. 실제 결과가 없으면 DB 실행을 Pass로 보고하지 않습니다.
결과 표만으로 앞선 검사 블록의 실행을 단정하지 않습니다. 파일 전체를 실행했다는 확인도 필요합니다.
임시 테이블 자동 정리는 CREATE TEMP TABLE, ON COMMIT DROP과 COMMIT을 코드에서 확인합니다.
실제 정리 여부는 같은 DB 세션에서 COMMIT 이후 확인한 근거가 있을 때만 실행 확인으로 보고합니다.
AI의 직접 DB 실행과 별도 정리 조회는 독자의 필수 완료 조건이 아닙니다.
필수 검사는 Pass·Fail·Not Run·검사 없음으로 구분하고, 범위 밖 항목은 별도로 표시합니다.

확인 범위는 작은 예제의 현재값·이력·참조 관계입니다. 권한 격리·동시 요청·운영 DB의
모든 삭제 조건은 이 검사의 근거로 보장하지 않습니다.
