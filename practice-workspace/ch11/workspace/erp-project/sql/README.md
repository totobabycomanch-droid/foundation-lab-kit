# AI가 작성한 SQL 보관 위치

이 폴더에 스키마 SQL을 저장하고 `lab.py apply 파일명.sql`로 적용합니다.
승인 함수와 테이블의 완성 SQL은 시작 키트에 미리 제공하지 않습니다.

- 적용 전 AI가 연결 명세와 생성 SQL을 검토합니다. 이 도구는 임의 SQL의 보안 샌드박스가 아닙니다.
- 스키마 파일에는 테이블·함수·인덱스 생성과 필요한 테이블 변경을 둡니다.
- 최상위 BEGIN·COMMIT·ROLLBACK, DROP·TRUNCATE·DELETE는 받지 않습니다. 도구가 적용과 이력을 한 트랜잭션으로 묶습니다.
- 함수 본문 내부의 PL/pgSQL BEGIN·END는 사용할 수 있습니다.
- 같은 파일·내용을 다시 적용하면 건너뜁니다. 적용한 파일을 수정했다면 새 파일로 변경을 설명합니다.
- 기본 데이터는 `lab.py prepare`, 재실습은 명시적인 `--case A --reset` 또는 `--case B --reset`으로 준비합니다.
- SQL 생성·파일 보존·DB 적용은 서로 다릅니다. 적용 결과가 실패하면 다음 작업으로 넘어가지 않습니다.

상위 `workspace/sql/00_initialize_lab.sql`은 이전 준비 방식입니다. 현재 최초 준비에는 `lab.py init`을 사용합니다.
기존 DB는 자동으로 이전하지 않으며, 개편 명세와 다른 개인 실습 데이터는 보존합니다.

## 완전 초기화 SQL

완전 초기화에는 상위 `workspace/sql/99_reset_lab.sql`을 사용합니다. 독자가 전체 실습 결과 삭제를 명시적으로 요청했을 때만 실행합니다.
`lab.py clear-database --confirm CHAPTER11`이 전용 연결 대조 후 실행하며, SQL Editor에서 파일 전체를 직접 실행할 수도 있습니다.
주문·재고·원장뿐 아니라 실습 표식·SQL 적용 이력과 두 업무 함수도 지웁니다. 지정 테이블의 소유 시퀀스도 함께 제거됩니다.
다른 객체·함수나 외부 의존성이 있으면 중단합니다. `CASCADE`를 추가하거나 검사를 제거하지 않습니다.
이 파일은 일반 스키마가 아니므로 `lab.py apply`로 적용하지 않습니다. 적용 이력에도 새로 등록하지 않습니다.
