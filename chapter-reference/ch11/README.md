# Chapter 11 주문 승인 참조 코드

이 자료는 Chapter 11의 DB·API·화면 연동이 막혔을 때 비교·복구하는 코드입니다.
기초 실습 키트 `foundation-kit-v1.3.33`에 포함된 시작 scaffold와 함께 사용합니다.
실습을 마쳤다면 다시 실행하거나 정상 코드를 교체할 필요가 없습니다.

## 파일과 비교 위치

| 파일 | 역할 | 기초 실습 키트에서 비교할 위치 |
| :--- | :--- | :--- |
| `approve_order.sql` | 테이블 세 개와 주문 승인 함수 | 독자가 SQL Editor에서 실행하고 보존한 SQL 실행본 |
| `main.py` | 요청 검사·DB 호출·커밋·롤백·CORS | `practice-workspace/ch11/workspace/erp-project/api/main.py` |
| `ApproveOrder.vue` | 요청·로딩·성공·오류·재시도·접근성 | `practice-workspace/ch11/workspace/frontend-project/src/components/ApproveOrder.vue` |
| `App.vue` | 주문 승인 카드 등록 | `practice-workspace/ch11/workspace/frontend-project/src/App.vue` |

## 사용하는 순서

1. ZIP은 기존 작업 폴더와 다른 빈 폴더에 압축을 풉니다. 위 위치는 파일을 전부 덮어쓰라는 뜻이 아닙니다.
2. 실패한 단계의 요청·응답·DB 상태를 확인하고, 관련 참조 파일만 비교합니다.
3. 기존 작업을 보존한 뒤 필요한 부분만 반영합니다. 변수명·CSS가 달라도 같은 동작이면 유지합니다.
4. 변경한 코드로 해당 실험을 다시 수행하고, 관찰 기록에 복구한 단계·사용한 코드·이유를 직접 적습니다.

SQL은 Chapter 11 전용 Supabase 프로젝트의 SQL Editor에서 독자가 직접 실행합니다.
`approve_order.sql`에는 CREATE TABLE이 있으므로 기존 테이블이 있는 DB에서 전체 재실행하지 않습니다.
현재 객체·정의와 필요한 변경부터 확인하고, 생성 SQL과 참조 SQL을 둘 다 실행하지 않습니다.
이 파일에는 고정 상품·주문 INSERT가 없습니다. 최초 등록과 실험별 복원은 원고의 11.2와 초기화 안내를 따릅니다.
실제로 성공한 SQL은 11.2의 보존 절차에 따라 별도 실행본으로 남깁니다. 내려받은 파일 자체는 실행 증거가 아닙니다.

API·프론트엔드는 참조 폴더에서 직접 실행하지 않습니다. 키트의 기존 의존성과 실행 폴더를 사용하고,
백엔드 연결값은 로컬 `.env`에서 설정합니다. 실제 연결값·비밀번호는 AI나 관찰 기록에 제공하지 않습니다.

## 학습용 구현의 범위

- 인증·회사 격리·서버 중복 승인 방지는 구현하지 않았습니다. 같은 주문을 다시 보내면 추가 차감될 수 있습니다.
- 화면의 버튼 잠금은 현재 화면에서만 추가 클릭을 막습니다.
- DB 오류 문자열과 서버 오류도 API의 400 응답으로 전달합니다. 내부 정보가 포함될 수 있으므로 운영용 오류 처리로 사용하지 않습니다.
- HTTP 요청 제한 시간과 저장 후 응답 유실에 대한 안전한 재시도는 구현하지 않았습니다.
- 코드 제공이 DB 실행·브라우저 동작·중간 실패 롤백·동시 요청 검증의 완료를 의미하지 않습니다.

원고의 11.5~11.8에 따라 직접 확인하고, 실행하지 않은 항목은 `Not Run`으로 남깁니다.
