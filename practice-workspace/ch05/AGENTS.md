# Chapter 5 작업 규칙

common-rules-version: chapter5-v4

## 작업 위치와 범위

- 현재 작업 폴더의 절대 경로를 확인하고 README.md와 sql/README.md를 읽는다.
- 생성 대상은 sql/01_current_and_history.sql과 sql/02_relationship_and_delete.sql이다.
- reference/는 막혔을 때 별도로 실행하는 선택 자료다. 생성·검토 요청에서 답안으로 읽거나 복사하지 않는다.
- 기존 파일을 조사하고 변경 대상과 검사 방법을 먼저 보고한다. 승인된 범위는 다시 승인을 요구하지 않는다.
- 다른 Chapter와 .archive/는 변경하지 않는다.

## DB 실행 규칙

- 기초 실습 전용 PostgreSQL에서만 실행한다. 운영·공용 DB에는 실행하지 않는다.
- sql/README.md의 스키마·시작 데이터·필수 검사·실행 구간을 따른다.
- 실습 1은 파일 전체를 BEGIN부터 COMMIT까지 실행한다.
- 실습 2는 같은 파일 안의 세 구간을 순서대로 실행한다. 각 구간은 독립된 BEGIN·검사·COMMIT을 갖는다.
- 구간 경계는 sql/README.md에 정한 주석을 사용한다. 독자에게 줄 번호나 DO 블록 일부 선택을 요구하지 않는다.
- 실습 1 전체와 실습 2 구간 1만 자기 실습 테이블을 명시된 순서로 초기화한다.
- ch05_lab의 지정 일반 테이블만 사용한다. 임시 테이블·ON COMMIT DROP·DROP SCHEMA·CASCADE는 금지한다.
- 다른 실습 테이블·스키마·업무 테이블·함수·권한 정책은 변경하지 않는다.
- 실습 2 구간 2는 실제 삭제를 시도한다. foreign_key_violation(23503) 또는 restrict_violation(23001)만 처리하고 삭제 성공은 검사 실패로 알린다.
- 구간 2·3은 필요한 테이블과 직전 완료 상태를 검사한다. 순서 누락·완료 구간 반복을 통과시키지 않는다.
- 예상 밖 오류를 숨기지 않는다. 실패한 구간은 필요하면 ROLLBACK 후 원인을 해결하고 해당 구간 전체를 다시 실행한다.
- 앞 구간에서 COMMIT한 데이터는 뒤 구간 실패로 취소되지 않는다. 처음부터 시작하려면 구간 1을 실행한다.
- .env, 비밀번호, API 키, JWT와 실제 DB 접속 정보를 읽거나 출력하지 않는다.

## 설명과 검증

- 파일 목적, 실행 단위, 초기화 범위와 재시작 방법을 짧은 주석으로 설명한다.
- 검사는 실제 조회값으로 판단하고 잘못되면 RAISE EXCEPTION으로 실패시킨다. 각 구간의 검사는 해당 COMMIT 전이다.
- 실제 조회값 요약은 보조 근거이며 자동 검사를 대신하지 않는다. 검사를 위한 상태 테이블이나 함수를 추가하지 않는다.
- Core는 실습 1·2의 업무 결과 조회·기록, AI 검토, 대표 검사 두 곳의 근거 확인과 자가 체크로 완료한다.
- 실습 간 데이터 보존 확인과 의도한 실패·원본 복구는 선택 활동이다. 미수행을 Core 실패·근거 부족으로 판정하거나 추가 제출을 요구하지 않는다.
- 자동 검사의 요구 수준은 선택 활동 여부와 관계없이 유지한다. 선택 활동을 이유로 필수 검사를 생략하지 않는다.
- AI 검증에는 실습 1 전체 실행 상태·조회 결과와 실습 2 세 구간 실행 상태·변경 전후 조회 결과를 사용한다.
- 앞선 완료 보고는 실제 실행 근거를 대신하지 않는다. 조회 결과 판정과 검사 코드 판정을 구분한다.
- 실행·조회 직후 하나의 기록 틀에 실제 결과를 남긴다. 기록한 탭은 닫거나 재사용할 수 있다. 선택 활동 결과는 별도로 남기며 Core 입력에 강제로 포함하지 않는다.
- 선택 활동에서 보존을 확인하려면 실습 1을 다시 초기화하기 전에 현재 수량·이력 내용·순서·행 수·합계를 비교한다.
- 선택 활동의 실패·복구는 SQL Editor의 사본과 저장된 원본을 구분한다. 위치 확인 보조 요청은 파일을 수정하지 않는다.
- Pass·Fail·Not Run·테스트 없음으로 실제 근거에 따라 보고한다. AI의 DB 직접 실행은 필수가 아니다.
- 전체 검사 항목의 누락과 오류는 AI가 검토한다. 독자는 대표 두 곳에서 조회·비교·실패 처리만 직접 확인하며 모든 검사 코드를 읽을 필요는 없다.
- 대표 검사 근거는 ch05/부터 시작하는 경로·실제 검색 구문·실패 조건으로 제시한다.
- 재시작은 데이터 초기화이며 업무 요청의 중복 처리 방지 기능이 아니다.
- 권한 격리·동시 요청·사용 중지 상품의 신규 거래 차단·실제 ERP 전체의 삭제 안전성은 검증 범위 밖이다.
