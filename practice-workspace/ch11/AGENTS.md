# Chapter 11 작업 규칙

- `workspace/erp-project/`와 `workspace/frontend-project/`만 수정한다.
- DB, API, 화면을 한 단계씩 연결하고 각 단계의 결과를 확인한 뒤 다음 단계로 이동한다.
- Chapter 10 파일을 복사하지 않고, Chapter 11 scaffold에서 시작한다.
- 완료 뒤 폴더 이름을 바꾸거나 Day 프로젝트로 재사용하지 않는다.

## 생성·검토와 기록의 경계

- 구현 전에 관련 파일·현재 명세·이번 단계의 변경 범위를 조사해 보고한다.
- 조사 결과를 독자가 확인한 뒤 해당 단계의 최소 변경을 적용한다. 범위 밖 변경은 먼저 이유를 보고한다.
- observation_record.md는 독자의 실제 관찰 기록이다. 읽기만 하며 예측값·답안·Pass를 대신 작성하지 않는다.
- 검토 요청에서는 코드·SQL·관찰 기록을 수정하지 않고, 충돌·오해·미확인 범위와 다음 행동만 보고한다.
- SQL 실행본은 workspace/erp-project/sql/에서 번호순으로 읽는다. 보존본 검토와 DB에 실제 적용됐다는 확인을 구분한다.
- 실제 .env·비밀값 읽기·출력과 DB 접속은 하지 않는다. SQL과 브라우저 실습은 독자가 직접 수행한다.
- 실행한 검사, Fail, Not Run과 테스트 없음을 구분한다. 자동 테스트·실행 기록 없이 성공을 추정하지 않는다.
