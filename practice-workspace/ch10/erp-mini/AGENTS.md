# Chapter 10 erp-mini 규칙

- `schema.sql`은 테이블·관계·제약 조건을 정의하고, `db.py`는 DB 연결을 담당한다.
- 이 장에서는 요청부터 저장까지 읽을 수 있도록 `server.py`에 HTTP 요청 처리, 업무 검사, SQL 실행과 커밋·롤백을 함께 작성한다. 별도 계층으로 분리하지 않는다.
- 주문·상세·원장·이벤트·초기 상태 이력 저장은 하나의 트랜잭션으로 처리한다.
- 실제 비밀번호는 `.env`에만 두고 코드나 결과 보고에 포함하지 않는다.
- DB 검증을 실행하지 못하면 성공으로 추정하지 않고 `Not Run`으로 보고한다.


## 화면 실습의 제공·생성 경계

- 기본 생성 범위는 server.py와 test_orders.py다. 공개 함수·입력·응답·DB 연결 규약은 README.md를 따른다.
- server.py가 DB 확정·취소를 담당한다. 제공 관찰 기능에 업무 저장을 맡기지 않는다.
- lab_app.py, lab_store.py, frontend/, verify_core.py, db.py, schema.sql, sql/는 제공 기능이다. 검사 통과를 위해 수정하지 않는다.
- 실패 장치는 양수 입력의 두 번째 상세 INSERT 직전에 실제 PostgreSQL 오류를 발생시킨다. 요청 검사를 제거해 실패를 만들지 않는다.
- 전용 검사 스키마의 생성·제거는 verify_core.py --allow-test-writes를 명시한 경우에만 허용된다. 기존 실습 테이블은 초기화하지 않는다.
- 참고 완성 코드를 자동 복사하지 않는다. 기존 구현이 있으면 조사·보완하고 변경 범위를 보고한다.
- 관찰 커서의 SQL 지원 범위는 README.md를 따른다. 독립 검사에서 public 등 다른 스키마를 명시하거나 제공 연결을 우회하지 않는다.
