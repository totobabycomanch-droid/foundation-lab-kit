# Chapter 5 작업 규칙

common-rules-version: chapter5-v3

## 작업 위치와 범위

- 현재 작업 폴더의 절대 경로를 확인하고 README.md와 sql/README.md를 읽는다.
- 생성 대상은 sql/01_current_and_history.sql과 sql/02_relationship_and_delete.sql이다.
- reference/는 독자가 막혔을 때 별도로 실행하는 선택 자료다. 생성·검토 요청에서 답안으로 읽거나 복사하지 않는다.
- 기존 파일을 조사하고 필요한 부분만 보완한다. 변경 대상과 검사 방법을 먼저 보고한다.
- 이미 승인받은 범위는 다시 승인을 요구하지 않는다. 다른 Chapter와 .archive/는 변경하지 않는다.

## DB 실행 규칙

- 기초 실습 전용 PostgreSQL에서만 실행한다. 운영·공용 DB에는 실행하지 않는다.
- sql/README.md의 공통 스키마와 시작 데이터를 따른다. 이 이름은 본문 SELECT 실행을 위한 규약이다.
- ch05_lab의 지정 일반 테이블만 사용하고 COMMIT 후 데이터를 보존한다. 임시 테이블·ON COMMIT DROP은 사용하지 않는다.
- 각 파일은 BEGIN부터 COMMIT까지 전체 실행한다. 시작 시 자기 실습 테이블만 명시된 순서로 삭제하고 다시 만든다.
- DROP SCHEMA, CASCADE, 다른 스키마·업무 테이블·함수·권한 정책의 생성·변경은 금지한다.
- 실습 2의 상품 삭제는 실제 시도한다. foreign_key_violation만 처리하고 삭제가 성공하면 검사 실패로 알린다.
- 다른 오류는 그대로 전달한다. 실패한 트랜잭션은 필요하면 ROLLBACK 후 전체 재실행한다.
- .env, 비밀번호, API 키, JWT와 실제 DB 접속 정보를 읽거나 출력하지 않는다.

## 설명과 검증

- 파일 목적, 전체 실행, 데이터 보존과 재실행 초기화 범위를 짧은 주석으로 설명한다.
- sql/README.md의 필수 검사를 실제 조회값으로 확인하고 RAISE EXCEPTION으로 실패를 알린다.
- 파일 끝에 실제 조회값을 모은 보조 표를 남긴다. 독자의 본문 SELECT와 자동 검사의 근거를 구분한다.
- AI 직접 실행, 독자 제공 결과와 코드 검토를 구분한다. Pass·Fail·Not Run·검사 없음으로 보고한다.
- 실제 실행하지 않았거나 검사가 없으면 Pass로 처리하지 않는다. AI 직접 DB 실행은 필수 완료 조건이 아니다.
- 근거는 ch05/부터 시작하는 경로와 실제 검색 구문으로 제시한다. 대표 검사 한 곳씩의 실패 조건을 설명한다.
- 두 번 실행과 직접 조회의 결과 일치, 실습 간 데이터 보존 여부는 제공된 증거로 판정한다.
- 재실행은 데이터 초기화이며 업무 요청의 중복 처리 방지 기능이 아니다.
- 권한 격리·동시 요청·실제 ERP의 삭제 안전성을 검증했다고 보고하지 않는다.
