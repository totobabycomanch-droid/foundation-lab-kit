# Chapter 3 예상 최종 판정

이 파일은 AI A와 AI B가 독립 판정을 완료한 뒤 비교 단계에서만 읽는다.

| 검토 항목 | 예상 판정 | 핵심 근거 |
|---|---|---|
| 본사 사용자 권한과 요청 주체·대상 회사의 분리 | `Pass(조건부)` | 요청 주체는 인증 정보, 등록 대상은 요청 본문으로 분리된다. 실제 토큰 검증은 스텁이다. |
| 같은 화면의 연속 클릭 방지 | `Pass(제한적)` | `isSaving`은 같은 화면 인스턴스의 재진입만 막는다. |
| 네트워크 재전송 식별 | `Fail` | 회사 등록 POST는 멱등 키를 보내거나 검사하지 않는다. |
| 같은 `corp_id`의 중복 행 방지 | `Pass(제한적)` | DDL에 `UNIQUE`가 있지만 이전 성공 응답 재사용과 실제 DB 충돌 응답은 별개다. |
| 가맹점·부서·관리자 사원의 원자 저장 | `Fail` | 개별 저장하며 하위 저장 예외를 삼키고 성공을 반환할 수 있다. |
| 재전송·동시 요청·하위 저장 실패 테스트 | `Fail(테스트 없음)` | 현재 자동 테스트에 해당 실패 시나리오가 없다. |
