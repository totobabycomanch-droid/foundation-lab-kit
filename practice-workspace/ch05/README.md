# Chapter 5 — 현재값·이력과 데이터 관계

AI가 두 SQL 예제를 만들고, 독자는 짧은 SELECT로 현재값·이력과 상품·거래 관계를 읽습니다.
API나 승인 함수를 만드는 실습은 아닙니다. 두 예제는 별도 시작 데이터를 사용합니다.

## 시작과 실행

1. VS Code에서 ch05/ 폴더를 엽니다.
2. AI가 AGENTS.md, README.md와 sql/README.md를 읽고 두 SQL 파일을 생성하도록 요청합니다.
3. 전용 Supabase SQL Editor에서 실습 1 파일 전체를 실행하고 현재 수량·이력·합계를 조회합니다.
4. 실습 2 파일은 구간 1 준비 → 구간 2 삭제 시도 → 구간 3 목록 제외 순서로 실행합니다.
   시작·끝 주석 사이 전체를 새 쿼리에 복사하며, 각 구간의 COMMIT 후 원고의 SELECT로 변경 전후를 확인합니다.
5. 각 실행·조회 직후 원고의 기록 틀 하나에 실제 결과를 남깁니다. 기록한 탭은 닫거나 다음 조회에 재사용해도 됩니다.
6. 채운 기록 표로 5.5의 AI 검토를 요청합니다. 전체 검사 항목은 AI가 검토하고 독자는 대표 두 곳의 조회·비교·실패 처리를 확인한 뒤 자가 체크합니다. 여기까지가 Core입니다.
7. 더 확인하고 싶을 때만 데이터 보존·의도한 실패·원본 복구를 선택해 진행합니다.
   선택 활동을 하지 않아도 Core를 완료할 수 있습니다. 파일 반복 실행은 별도 필수 과제가 아닙니다.

| 생성 파일 | 실행 단위와 확인할 결과 |
|---|---|
| sql/01_current_and_history.sql | 전체 실행: 현재값 7, 입고 10·출고 -3 두 행과 합계 7 |
| sql/02_relationship_and_delete.sql | 세 구간: 목록 1건·연결 확인 → 실제 삭제 차단 → 목록 0건·연결 보존 |

실습 1 전체와 실습 2 구간 1만 해당 실습을 초기화합니다. 실습 2는 실습 1 테이블을 변경하지 않습니다.
실습 2 구간 2·3은 앞 구간의 완료 상태가 필요하며, 완료 구간을 다시 실행하면 사전 검사가 실패합니다.
실패한 구간은 원인 해결 후 필요하면 ROLLBACK하고 해당 구간 전체를 다시 실행합니다.
앞 구간에서 확정한 데이터는 유지됩니다. 처음부터 다시 시작하려면 구간 1을 실행합니다.
공통 이름과 검사는 [sql/README.md](sql/README.md)를 따릅니다.

막혔을 때만 [reference/README.md](reference/README.md)의 참고 SQL을 별도로 실행합니다.
같은 실습 데이터가 초기화되므로 생성 파일의 결과부터 기록하고, 참고 결과와 구분합니다.
.archive/와 이전 초기화·리셋 SQL은 사용하지 않습니다.
