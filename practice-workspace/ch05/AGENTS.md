# Chapter 5 작업 규칙

common-rules-version: chapter5-v2

## 작업 위치와 범위

- 현재 작업 폴더의 절대 경로를 확인하고 이 파일 옆의 README.md와 sql/README.md를 읽는다.
- 생성 대상은 sql/01_current_and_history.sql과 sql/02_relationship_and_delete.sql 두 파일이다.
- reference/는 독자가 비교할 참고 자료다. 생성·검토 요청에서 답안으로 읽거나 복사하지 않는다.
- 기존 생성 파일이 조건을 충족하면 재작성하지 않고 필요한 부분만 검토한다.
- 변경 대상과 검사 방법을 먼저 보고한다. 이미 승인받은 범위는 다시 승인을 요구하지 않는다.
- 다른 Chapter, 기존 업무 테이블과 .archive/ 보관 파일은 읽거나 수정하지 않는다.

## DB 안전 조건

- SQL은 기초 실습 전용 PostgreSQL에서만 실행한다. 운영·공용 DB에는 실행하지 않는다.
- 두 파일은 독립적으로 실행한다. BEGIN부터 COMMIT까지 전체 실행할 때 매번 새 임시 테이블에서
  시작하고 ON COMMIT DROP으로 정리한다. 영구 테이블·함수·권한 정책을 생성하거나 바꾸지 않는다.
- 실패한 작업의 트랜잭션이 열려 있다면 ROLLBACK으로 취소하고 수정한 파일 전체를 다시 실행한다.
- 삭제 시도에서 foreign_key_violation만 예상 오류로 처리한다. 삭제가 성공하면 검사 실패를
  발생시키고, 다른 오류는 그대로 전달한다.
- .env, 비밀번호, API 키, JWT와 실제 DB 접속 정보를 읽거나 출력하지 않는다.

## 설명과 검증

- SQL의 목적, 전체 실행 단위와 중요한 검사의 이유를 짧은 주석으로 설명한다.
- sql/README.md의 필수 검사를 실제 테이블 조회값으로 확인한다. 예상값만 SELECT해서 출력하지 않는다.
- AI가 직접 실행한 결과, 독자가 제공한 실행 결과와 코드 검토를 구분한다.
- Pass·Fail·Not Run·검사 없음으로 보고한다. 실행하지 않았거나 검사가 없으면 Pass로 처리하지 않는다.
- 범위 밖 항목은 필수 검사의 미실행·누락과 구분한다. AI 직접 DB 실행과 별도 정리 조회를 독자의 추가 완료 조건으로 요구하지 않는다.
- 근거에는 ch05/부터 시작하는 정확한 파일 경로와 파일에 실제로 존재하는 검색 구문을 함께 적는다.
- 권한 격리, 동시 요청이나 실제 ERP의 삭제 안전성을 검증했다고 보고하지 않는다.
