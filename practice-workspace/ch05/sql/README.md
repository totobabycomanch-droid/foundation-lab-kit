# Chapter 5 SQL 실행과 필수 검사

## 실행 단위와 변경 범위

기초 실습 전용 PostgreSQL을 사용합니다. 실습 1은 파일 전체를 BEGIN부터 COMMIT까지 실행합니다.
실습 2는 한 파일 안의 세 구간을 순서대로 실행하며, 각 구간은 독립된 BEGIN·검사·COMMIT으로 끝납니다.
COMMIT한 데이터는 ch05_lab의 일반 테이블에 남아 다른 쿼리에서도 조회할 수 있습니다.
임시 테이블·ON COMMIT DROP·DROP SCHEMA·CASCADE와 다른 스키마·업무 테이블·함수·권한 변경은 금지합니다.

실습 1 전체와 실습 2 구간 1에서만 CREATE SCHEMA IF NOT EXISTS ch05_lab를 실행하고,
자기 실습 테이블만 DROP TABLE IF EXISTS로 삭제한 뒤 다시 만듭니다.

| 파일 | 초기화 대상과 삭제 순서 |
|---|---|
| 01_current_and_history.sql | ch05_lab.lab_stock_history → ch05_lab.lab_stock |
| 02_relationship_and_delete.sql 구간 1 | ch05_lab.lab_trade → ch05_lab.lab_delete_attempt → ch05_lab.lab_product |

실습 2는 실습 1의 현재고·이력을 보존합니다. 재시작은 데이터를 다시 만드는 것이며 업무 요청의 중복 처리 방지가 아닙니다.

## 실습 2의 세 실행 구간

생성 SQL과 참고 SQL 모두 아래 주석을 정확히 사용합니다. 각 시작·끝 주석 사이 전체가 실행 단위입니다.
각 구간은 자기 BEGIN과 COMMIT을 포함합니다. 줄 번호나 DO 블록 일부를 선택하게 하지 않습니다.

| 경계 주석 | 수행할 작업 | 확정할 상태 |
|---|---|---|
| -- [구간 1 시작] / -- [구간 1 끝] | 실습 2 초기화와 시작 데이터 생성 | 목록 1건, 상품·거래 각각 1건, 연결 정보 정확, is_deleted=false, 차단 기록 0행 |
| -- [구간 2 시작] / -- [구간 2 끝] | 직전 상태 확인, 실제 상품 삭제 시도, 예상 오류 처리 | 목록 1건, 상품·거래와 연결 유지, 차단 기록 1행·blocked=true·SQLSTATE 23503 또는 23001 |
| -- [구간 3 시작] / -- [구간 3 끝] | 직전 상태 확인, 목록 제외 표시 변경 | 목록 0건, 상품·거래 각각 1건과 연결 유지, is_deleted=true, 차단 기록 유지 |

구간 2·3은 필요한 테이블이 있는지 먼저 확인하고 위 표의 직전 상태를 실제 데이터로 검사합니다.
순서 누락과 완료 구간 반복은 실패해야 합니다. 구간 2·3에서 초기화하거나 차단 기록을 지우지 않습니다.
구간 2는 DELETE에서 발생한 foreign_key_violation(23503) 또는 restrict_violation(23001)만 내부 예외 블록으로 처리합니다.
ON DELETE RESTRICT 차단은 PostgreSQL 17에서는 23503, 18에서는 23001로 기록됩니다. 실제 오류 코드를 그대로 남깁니다.
실제 오류의 SQLSTATE를 기록하고, 삭제가 성공하면 RAISE EXCEPTION으로 실패시킵니다. 다른 오류는 그대로 전달합니다.
검사용 상태 테이블·함수는 추가하지 않습니다. 업무 데이터와 차단 기록으로 실행 순서를 판단합니다.

## 실패와 재시작

오류가 나면 다음 구간으로 넘어가지 않습니다. 필요하면 ROLLBACK 후 원인을 해결하고 실패한 구간 전체를 실행합니다.
앞 구간에서 COMMIT한 데이터는 유지되므로 파일 전체가 취소됐다고 설명하지 않습니다.
처음부터 시작하려면 구간 1부터 실행합니다. 완료한 구간 2·3을 그대로 반복하면 사전 검사에서 실패합니다.
실습 1은 오류 해결 후 파일 전체를 다시 실행합니다. 남은 데이터만으로 새 실행의 성공을 판단하지 않습니다.

## 본문 SELECT와 연결할 공통 스키마

아래 이름·시작 데이터는 본문의 조회문을 위한 규약입니다. 검사 변수명과 DO 블록 구성은 고정하지 않습니다.
추가 실습 테이블은 만들지 않습니다. seq와 각 id는 자동 증가로 만들며 값을 직접 입력하지 않습니다.
첫 이력은 seq 1, 두 번째는 seq 2가 되도록 같은 문장에서 순서대로 입력합니다.

| 테이블 | 필수 컬럼과 규칙 |
|---|---|
| ch05_lab.lab_stock | product_code text 기본 키, quantity integer NOT NULL |
| ch05_lab.lab_stock_history | seq integer 기본 키, product_code text, change_qty integer, reason text; 필수 값은 NOT NULL |
| ch05_lab.lab_product | id integer 기본 키, code text UNIQUE, name text, is_deleted boolean 기본값 false; 필수 값은 NOT NULL |
| ch05_lab.lab_trade | id integer 기본 키, trade_no text UNIQUE, product_id integer 외래 키, quantity integer 양수; 필수 값은 NOT NULL |
| ch05_lab.lab_delete_attempt | blocked boolean NOT NULL, sqlstate text NOT NULL |

실습 1은 A001의 현재 수량을 10에서 7로 바꾸고, seq 1에 A001·10·입고, seq 2에 A001·-3·출고를 남깁니다.
실습 2는 A001·샘플 상품과 T-0001·수량 5를 만듭니다. lab_trade.product_id는 lab_product.id를 참조합니다.
거래가 참조하는 상품의 물리 삭제를 차단하고, 실제 오류에서 얻은 blocked=true와 sqlstate 23503 또는 23001을 한 행으로 남깁니다.
구간 3에서만 is_deleted를 true로 바꾸며 목록은 false인 상품만 조회합니다. 신규 거래 차단은 구현하지 않습니다.
상품에서 조회한 이름은 현재 이름입니다. 거래 당시 상품명·단가의 별도 보존은 범위 밖입니다.

## 자동 검사와 독자의 직접 조회

각 실행 단위는 실제 조회값이 잘못되면 RAISE EXCEPTION으로 실패합니다. 자동 검사는 해당 COMMIT 전에 수행합니다.
실습 1은 현재 수량 7, 이력 두 행의 상품·순서·수량·사유·행 수와 합계 7을 각각 검사합니다.
현재고 테이블 전체는 A001 1행, 이력 테이블 전체는 A001 2행이어야 합니다.
행 수는 상품코드로 필터링하지 않고 검사해 다른 상품의 행이 추가된 경우도 실패시킵니다.
합계가 같아도 내용이나 순서가 다르면 실패해야 합니다.
실습 2는 각 구간의 직전·완료 상태를 위 표대로 검사합니다. 상품·거래 각각의 행 수와
거래번호·상품코드·현재 상품명·수량·목록 제외 표시를 모두 검사합니다.
차단 기록은 구간 1에서 0행, 구간 2·3에서 정확히 1행이며 blocked=true, sqlstate는 23503 또는 23001이어야 합니다.
파일 또는 구간 끝의 실제 조회값 요약은 보조 근거이며 자동 검사를 대신하지 않습니다.

실습 1은 5.1의 업무 회의 → 5.2의 첫 파일 조사·생성 → 5.3의 실행·조회·AI 검토·결과 설명으로 마칩니다.
실습 2는 5.4에서 새 업무 회의 → 둘째 파일 조사·생성 → 세 구간 실행·조회·AI 검토·결과 설명을 진행합니다.
독자는 각 실습의 기록 틀에 실제 결과를 남기며, 기록한 탭은 닫거나 재사용할 수 있습니다.
해당 실습의 전체 검사 항목의 누락과 오류는 AI가 검토하고, 독자는 대표 한 곳의 조회·비교·실패 처리를 확인합니다.
실습 1 검토에는 첫 파일 전체 실행 상태·현재 수량/입고·출고 기록/합계만 사용합니다.
실습 2 검토에는 세 구간 실행 상태·목록과 거래의 변경 전후 조회·삭제 차단 기록과 재조회 결과를 사용합니다.
두 실습을 완료하면 5.5의 Core 완료를 확인합니다. 두 기록을 합치거나 통합 AI 검토를 다시 받을 필요는 없습니다.

실습 간 데이터 보존 확인과 의도한 실패·원본 복구는 선택 활동입니다. 이를 수행하지 않았다는 이유로
Core 실패나 근거 부족으로 판정하거나 추가 제출을 요구하지 않습니다. 자동 검사 자체는 위 기준을 모두 유지합니다.
선택 활동에서 보존을 확인하려면 실습 1 초기화 전에 현재 수량·이력의 내용·순서·행 수·합계를 비교합니다.
이후 사본으로 의도한 실패를 확인하고 원본을 복구했다면 첫 기록 아래에 결과를 별도로 남깁니다.
조회가 맞는 것과 검사 코드가 적절한 것은 별도로 판정합니다. 회의와 같은 표현으로 업무 결과는 확인됨·다름·미확인,
검사 코드는 적절·보완 필요·미확인으로 보고합니다. 검사 누락은 보완 필요입니다. 실행하지 않은 검사는 Pass로 보고하지 않습니다.
AI의 직접 실행 결과는 Pass·Fail·Not Run, 검사가 없으면 테스트 없음으로 구분합니다. AI 직접 DB 실행은 필수가 아닙니다.
담당자에게는 실제 확인한 결과로 설명합니다. 별도 보고문이나 원고 예시 답변 복사는 요구하지 않습니다.
권한 격리·동시 요청·실제 ERP 전체의 삭제 안전성은 검증 범위 밖입니다.
