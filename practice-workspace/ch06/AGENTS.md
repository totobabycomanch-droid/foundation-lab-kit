# Chapter 6 작업 규칙

- 이 장에서는 도구와 실행 환경을 조사하며 업무 기능을 구현하지 않는다.
- 실제 `.env` 값은 읽거나 출력하지 않는다.
- 이 장은 이후 Chapter 7~11과 Day 00에서 쓸 모든 도구를 한 번에 준비하고 확인하는 장이다.
  Python, Node.js, npm, Docker와 Supabase의 준비 여부를 각각 판정한다.
- 실행하지 않았거나 설치하지 않은 도구 때문에 할 수 없는 개별 검증은 `Not Run`으로 보고한다.
- `Not Run`은 개별 검증 결과에만 사용하며 성공 근거로 삼지 않는다. 환경 준비 상태와 구분한다.
- `environment_report.md`는 하나의 표로 작성한다. 열은
  `항목 | 확인 기준 | 실제 확인 결과 | 상태 | 필요한 조치`다.
- 표의 항목은 작업 도구(VS Code·PowerShell·Git과 AI의 파일 읽기), Python 3.12,
  ch07/.venv의 Python 3.12와 실행 경로, 표준 라이브러리(SQLite 조회·unittest import),
  Node.js 24·npm, Docker(WSL 최소 요구사항과 CLI·Client·Server·Compose v2),
  Supabase(이번 장에서 실행한 `connection_check = 1`)다.
- 상태는 `Ready`와 `Needs Fix`만 허용한다. 확인 기준을 충족하는 실제 근거가 있는 경우에만
  `Ready`를 쓰고, 실패·기준 미달·미실행 또는 근거 부족은 `Needs Fix`로 남긴다.
  나중으로 미루는 상태는 두지 않는다.
- Supabase는 과거 실습 이력이 아니라 이번 장에서 실행한 확인 쿼리 결과만 근거로 삼는다.
  조회 성공을 전용 DB 구성이나 애플리케이션 연결 확인으로 확대하지 않는다.
- 환경 문서 작성 요청은 아래 허용된 확인과 `environment_report.md` 작성·갱신까지 승인한 요청이다.
  계획 승인이나 결과 입력 양식을 다시 요구하지 않고 진행한다. 공통 작업 순서의 승인 대기는
  이 범위에 적용하지 않는다. 설치·설정 변경은 이 승인에 포함되지 않는다.
- 상위 지침의 다른 Chapter 접근 금지에 대한 예외는 `../ch07/.venv/pyvenv.cfg` 조회와
  `../ch07/.venv/Scripts/python.exe`의 존재·버전·실행 경로 및 아래 표준 라이브러리 확인뿐이다.
  ch07 업무 코드와 데이터, 그 밖의 Chapter는 읽거나 수정하지 않는다.
- 모든 항목이 `Ready`이고 환경 문서의 AI 검증·독자 자가 체크를 마쳐야 Chapter 6이 완료되고
  Chapter 7로 이동할 수 있다. 하나라도 `Needs Fix`이면 Chapter 6 미완료로 보고한다.
- 도구를 준비했다는 사실을 ERP의 API·DB 연결이나 컨테이너 서비스 실행 완료로 표현하지 않는다.

## 환경 자동 확인과 문서 작성

- 독자에게 버전·경로·날짜를 정리해 빈칸에 넣으라고 요구하지 않는다. 먼저 접근 가능한 환경을
  직접 확인하고, 불가능한 항목만 하나씩 쉬운 행동으로 안내한다. 긴 로그 전체를 요구하지 않는다.
- VS Code에서 연 폴더와 AI 명령 실행 환경이 같은 PC인지 확인한다. 원격·컨테이너 환경이면
  그 환경의 결과를 독자의 Windows PC 결과로 기록하지 않는다. 접근 불가 항목은 Needs Fix다.
- 변경 전에 ch06의 파일 목록, README.md·AGENTS.md·.env.tools.example과 기존 보고서의 내용을
  비교 기준으로 확보한다. 비밀 파일과 파일 전문은 출력하지 않는다. 보고서 외에 파일을 만들지 않는다.
- 허용 명령은 현재 위치·실행 환경 확인, Get-Command로 경로 조사, 확인한 실행 파일의
  버전 조회와 Python의 sys.executable 조회, npm.cmd --version, git --version,
  wsl --version, docker --version, docker version, docker compose version이다.
  Docker Desktop·서비스·컨테이너를 시작하거나 재시작하지 않는다.
- Python은 실제 설치된 런타임 실행 파일을 확인한 뒤 전체 경로와 PowerShell의 &로 실행한다.
  WindowsApps 별칭, pymanager·py와 경로 없는 python은 실행하지 않는다. Manager 자체 업데이트나
  런타임 자동 설치를 피한다. 위치를 확정할 수 없으면 설치를 시도하지 말고 미확인으로 남긴다.
- Node.js·npm은 실제 사용 중인 실행 경로를 기록한다. 버전 관리자 shim이 자동 다운로드를
  일으킬 수 있으면 실제 설치 파일을 먼저 확인한다. 새 런타임이나 패키지 다운로드는 금지한다.
- ch07 가상환경은 해당 python.exe를 -B 옵션으로 직접 실행해 버전·sys.executable을 확인한다.
  같은 실행 파일로 sqlite3·unittest를 import하고 메모리 DB의 SELECT 1 결과가 (1,)인지 확인한다.
  업무 코드를 import하거나 실습 서버·검사 스크립트를 실행하지 않는다. DB 파일·캐시는 만들지 않는다.
- WSL 최소 기준은 Docker 공식 Windows 요구사항에서 현재 기준과 확인 날짜를 함께 기록한다.
  공식 기준에 접근할 수 없으면 충족을 추정하지 말고 독자에게 해당 페이지의 조건 확인만 안내한다.
- Supabase는 사용 가능한 브라우저 도구와 이미 로그인된 기초 실습 전용 프로젝트가 확인된
  경우에만 SQL Editor에서 SELECT 1 AS connection_check를 확인한다. 프로젝트가 불명확하면 실행하지 않는다.
  자격증명·.env를 읽거나 로그인 정보를 요청하지 않으며 CLI 로그인·프로젝트 생성·DB 직접 접속은 하지 않는다.
  도구가 없으면 독자에게 본문의 SQL Editor 확인 단계 링크와 함께 같은 쿼리 실행을 안내한다.
  독자가 확인한 날짜와 결과 1만 답하면 충분하다. AI 직접 실행과 독자 확인을 구분한다.
- 각 확인의 날짜·실행 환경·명령·핵심 결과를 보고서에 남긴다. 날짜는 실제 확인 시점에서 얻고
  과거 대화나 설치 성공 메시지로 현재 성공을 추정하지 않는다. 미실행·실패는 그대로 기록한다.
- 보고서 말미에 읽은 지침, 비밀정보 기록 여부, 변경 파일과 변경 범위 비교 결과를 짧게 남긴다.
  기존 미확인 기록은 보존하고, 이번 작업의 전후 비교와 diff로 보고서만 바뀌었는지 확인한다.
  비교 기준이 없으면 해당 변경 범위 검증은 Not Run으로 남긴다.
- 답변은 준비된 항목·아직 확인할 항목·다음 행동으로 간결하게 설명한다. 독자에게 확인이
  필요하면 가장 먼저 할 행동 하나만 안내하고, 답을 받은 뒤 보고서를 갱신한다.
  안내 중에도 이미 확인한 항목의 보고서는 작성하며, 모든 항목 Ready 전에는 완료로 쓰지 않는다.
- 문서 검증 요청에서는 지침·보고서·이번 확인 근거와 변경 내역을 대조한다. 필요한 항목만
  위 허용 범위로 다시 검사한다. 파일 수정은 하지 않고 실제 불일치와 미확인을 구분한다.
  문서가 Ready라고 썼다는 이유만으로 검증을 통과시키지 않는다.

## 진단 요청 규칙

- 도구 설치·확인 오류의 진단을 요청받으면 읽기 전용으로 조사한다. 파일, 시스템 설정, PATH,
  PowerShell 실행 정책과 기존 도구를 변경·삭제·교체하지 않으며, 승인 전에는 어떤 조치도 실행하지 않는다.
- 보고는 다음 다섯 항목으로만 한다.
  1. 준비 상태: `Ready` 또는 `Needs Fix`
  2. 확인 근거: 실제 버전과 실행 경로
  3. 원인 판단: 확인된 사실과 원인 후보를 구분해 세 문장 이내로 쓴다. 근거가 부족하면
     원인을 단정하지 말고 추가로 필요한 읽기 전용 확인과 이유를 제시한다.
  4. 필요한 조치: `Ready`이면 `조치 없음`. `Needs Fix`이면 최소 조치, 변경 대상·영향,
     관리자 권한·재시작 필요 여부와 되돌리는 방법을 제안한다.
  5. 검증 명령: 같은 기준으로 다시 확인하는 명령
- `Ready`이면 재설치, 업그레이드와 PATH 변경을 제안하지 않는다.
- 도구별 판정 기준과 추가 금지 사항은 진단 요청의 내용을 함께 적용한다.
