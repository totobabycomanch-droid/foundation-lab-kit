# Chapter 10 작업 규칙

- `erp-mini/`는 Chapter 10 전용이며 Chapter 9의 동명 폴더와 다른 프로젝트다.
- SQL은 폐기 가능한 Chapter 10 전용 Supabase 프로젝트 또는 로컬 PostgreSQL에서만 실행한다.
- `.env`와 실제 DB URL을 읽거나 출력하지 않는다.
- `DROP`과 `DELETE` 전에 현재 DB와 대상 테이블을 보고하고 승인받는다.


- 화면 실습의 기본 변경 범위는 erp-mini/server.py와 erp-mini/test_orders.py다. 자세한 공개 규약은 README.md를 따른다.
- verify_core.py --allow-test-writes는 이번 실행에서 새로 만든 ch10_verify_<UUID> 스키마의 생성·제거만 허용하며 기존 public 업무 테이블은 변경하지 않는다.

## AI 조사·구현 공통 절차

- 현재 작업 폴더와 실행 환경을 직접 확인하고, 확인하지 못한 사항은 추측하지 않는다.
- 이 폴더의 README.md와 작업 대상 하위 폴더의 AGENTS.md·README.md를 읽고 현재 구현, 제공 화면과 검사를 조사한다. 입력·응답 형식, 오류 처리와 저장 범위는 제공 규약을 따른다.
- 아직 파일을 수정하지 않고 변경할 파일과 이유, 검증 계획을 한국어로 보고한 뒤 사용자의 구현 승인을 기다린다.
- 승인 후에는 보고한 범위에서 구현한다. 범위 밖 변경이 필요하면 적용 전에 파일과 이유를 보고하고 승인을 기다린다.
- 기존 구현을 시작본이나 참고 완성 코드로 덮어쓰지 않는다.

## 구현 범위와 코드 설명

- 주문 저장 업무와 DB 없이 실행하는 업무 테스트만 구현한다. 기본 변경 파일은 위의 두 파일이며 별도 계층은 추가하지 않는다.
- 실제 DB 결과는 제공된 독립 검사로 확인하고, 같은 검사를 새로 만들지 않는다.
- 제공 화면·DB 연결·스키마·실패 장치·독립 검사는 변경하지 않는다.
- 인증·동시 출고·멱등성·주문 취소 기능은 추가하지 않는다.
- 생성·수정하는 함수에는 역할과 주요 입력·반환값, 실패 처리를 설명하는 짧은 한국어 docstring을 작성한다.
- 단가 결정, 재고 확인·차감, 전체 저장·취소와 연결 정리 부분에는 업무상 이유를 설명하는 짧은 주석을 붙인다. 줄별 해설은 피한다.

## 검증·보호·결과 보고

- 업무 테스트와 제공 독립 검사를 실행한다. 독립 검사는 이 문서와 README.md에 명시된 실행 조건 및 DB 쓰기 허용 범위를 따른다.
- 위의 임시 검사 스키마 생성·제거는 제공 독립 검사에 `--allow-test-writes`를 명시해 실행할 때만 허용한다. 이 허용을 기존 실습 데이터의 삭제나 초기화에 적용하지 않는다.
- 실습 중인 주문·가격을 초기화하거나 삭제하지 않는다. `.env` 내용·비밀번호·연결 문자열을 직접 읽거나 출력하지 않는다.
- 결과는 한국어로 보고한다. 변경 파일, 검사별 명령·실제 결과 요약과 Pass·Fail·Not Run, 화면 실습을 막는 문제를 포함한다.
- 화면 관찰, DB 없는 대역 테스트, 실제 DB 검사 근거를 구분한다. 대역 테스트를 실제 DB 검사의 통과 근거로 사용하지 않는다.
- 실행하지 못한 검사는 이유와 함께 Not Run으로 보고하고 성공으로 추정하지 않는다. `Ran 0 tests`도 통과 근거로 사용하지 않는다.

## 검증 요청을 받았을 때

- 검증 단계에서는 파일을 수정하거나 기존 구현을 덮어쓰지 않는다. 실패 원인과 다음 행동을 보고하고, 코드 보완이 필요하면 별도의 변경 계획을 먼저 제시한다.
- 이번 변경 파일과 diff 또는 비교 기준을 확인한다. 확인할 수 없는 변경 범위는 추측하지 않고 보고한다.
- 실행 근거가 확인되고 코드가 바뀌지 않은 기존 검사 결과는 재사용한다. 코드 변경·실패·미실행·근거 부족이 있는 검사만 추가 실행한다.
- 실습 중인 주문·가격을 초기화하거나 삭제하지 않는다. 제공 독립 검사에는 기존에 정한 임시 스키마 생성·제거 조건만 적용하며, 비밀정보 보호 규칙을 유지한다.
- 화면 관찰·대역 테스트·실제 DB 검사 결과를 구분하고, 미실행은 Not Run과 이유를 적는다.
- 회사 격리·동시 출고·멱등성·업무상 주문 취소는 이번 Core의 검증 대상이 아니다. 이를 통과로 판정하지 않는다.
