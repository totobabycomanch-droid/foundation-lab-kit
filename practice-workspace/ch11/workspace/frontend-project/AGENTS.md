# Chapter 11 frontend 규칙

- [연결 명세](../../connection_spec.md)와 [Chapter 지침](../../AGENTS.md)을 먼저 읽고 기존 화면·의존성을 조사한다.
- Vue Options API와 기존 Axios를 사용한다. 새 프로젝트·별도 CSS 라이브러리는 만들지 않는다.
- DB에서 조회한 정상 A·부족 B를 이름으로 구분하고 상품·수량·현재고·주문 상태·승인 버튼을 표시한다.
- 수량 입력란·별도 수량 저장 버튼을 제공하고 저장된 수량과 입력값을 구분한다. 저장 후 DB를 다시 조회한다. 미저장·잘못된 입력은 승인을 차단하고 승인 완료 후에는 입력·저장을 잠근다.
- UUID 복사·입력을 요구하지 않는다. 조회된 주문의 값으로 API에 요청한다.
- 조회 중·빈 결과·조회 실패와 승인 처리 중·성공·업무 거절을 구분한다.
- 요청 중에는 추가 클릭을 막고, 이미 승인된 주문은 조회 상태를 기준으로 승인 버튼을 잠근다.
- 승인 성공 뒤 DB 상태를 재조회한다. 화면 재고를 직접 차감하거나 성공 변수만 변경하는 것으로 완료하지 않는다.
- 저장 성공 뒤 재조회 실패는 별도로 알리고 재조회 경로를 제공한다. 저장 실패로 표시하지 않는다.
- 부족 거절은 사유를 보여 주고 완료 상태로 바꾸지 않는다. 다음 요청 시작 시 이전 오류를 지운다.
- 응답 유실은 처리 결과 미확인으로 안내하고 재조회로 상태를 확인하게 한다. 무조건 재승인하거나 실패로 단정하지 않는다.
- 화면 잠금과 서버 재승인 방지를 구분한다. 실제 비밀값을 프론트엔드 코드에 넣지 않는다.
- 키보드 사용과 좁은 화면에서 정보·결과를 읽을 수 있어야 한다. 복잡한 원장 검증 패널은 추가하지 않는다.
- 기존 빌드 명령을 실행하고 서버 접속을 확인한다. 빌드 성공·HTTP 접속·브라우저 동작 확인을 구분해 보고한다.
- 독자의 정상·부족 테스트 전에 자동 검사로 A·B를 소비하지 않는다. 직접 확인하지 않은 화면 동작은 `Not Run`이다.
