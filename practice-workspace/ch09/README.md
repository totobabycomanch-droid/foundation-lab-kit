# Chapter 9 — 작은 주문의 상태 규칙 확인

허용된 행동만 주문 상태를 바꾸고, 거부된 행동 뒤에도 기존 상태가 남는지 확인합니다.
Python 3.12의 표준 라이브러리만 사용합니다. 코드 생성·실행은 9.4에서 마치고,
9.5~9.7에서는 업무 책임과 실제 ERP의 DB 저장 구조를 읽습니다.

## 시작 전에 읽을 지침

- [상위 공통 지침](../AGENTS.md): 작업 순서, 변경 범위와 결과 보고 방법
- [Chapter 9 지침](AGENTS.md): 이번 장의 범위와 실행 방법
- [주문 예제 지침](erp-mini/AGENTS.md): 공개 메서드, 상태 표시와 테스트 기준

생성 대상은 `erp-mini/domain/order.py`, `erp-mini/main.py`,
`erp-mini/tests/test_erp_flow.py` 세 파일입니다. 원고의 생성 요청으로 작성합니다.

## 실행 순서

PowerShell 위치를 이 `ch09/` 폴더로 유지하고 원고의 순서대로 실행하세요.

| 명령 | 확인할 내용 |
|---|---|
| `./run.ps1 check` | 키트 시작 구조 확인 |
| `./run.ps1 demo` | 생성한 예제의 정상 흐름과 거부 결과 |
| `./run.ps1 shell` | `>>>`에서 한 줄씩 입력해 같은 주문의 상태 관찰. 끝나면 `exit()` |
| `./run.ps1 test` | 생성 테스트 결과 |
| `./run.ps1 verify` | 책의 업무 규칙으로 작성된 고정 검사 결과 |

예제와 테스트를 생성한 뒤 `demo`부터 진행합니다. 관찰·검사 결과를 원고의 Step 4에서
AI 검토와 비교하고, Step 5의 세 항목을 확인해 완료를 판정합니다.

## 선택 실습과 복구

결함 주입은 원고의 안내에 따라 별도 `fault-lab/order.py`에서만 수행하고
`./run.ps1 fault`로 검사합니다. `checks/`와 `reference/`는 수정하지 않습니다.

정상 생성·검증 중에는 `reference/`를 답안으로 읽거나 복사하지 않습니다.
실패 원인을 찾기 어려울 때 원고 Step 5의 안내에 따라 `reference/README.md`를 읽고 비교합니다.
다시 생성하려면 원고 9.8에 따라 보관할 파일을 복사하고 `./run.ps1 reset`으로 대상을 확인한 뒤
`./run.ps1 reset -Apply`를 실행합니다.
