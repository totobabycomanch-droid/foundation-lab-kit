# Chapter 11 backend 규칙

- [연결 명세](../../connection_spec.md)와 [Chapter 지침](../../AGENTS.md)을 먼저 읽고 현재 구현을 조사한다.
- 핵심 저장 규칙은 DB 함수에 두고 API는 입력 검사·함수 호출·트랜잭션 정리·응답과 조회를 연결한다.
- 기존 SQLAlchemy·psycopg2 동기 호출을 사용하고 API 경로 함수는 일반 `def`로 작성한다.
- 기존 의존성을 우선 사용한다. 범위 밖 파일·의존성 변경이 필요하면 이유를 보고한다.
- 실제 `.env`를 열거나 출력하지 않는다. 실행 도구·API·검사 프로세스가 로컬 `DATABASE_URL`을 사용하는 것은 허용한다.
- 전용 DB 확인을 통과한 뒤 생성 SQL을 파일로 저장·적용하고 결과를 직접 확인한다. SQL 복사·적용을 독자의 기본 작업으로 남기지 않는다.
- DB 스키마 준비·데이터 준비·상태 조회·사례 재준비를 구분한다. 기존 객체를 삭제하거나 자동 이전하지 않는다.
- 승인 함수는 주문 행 잠금 뒤 최신 상태를 검사하고 재승인을 막는다. 재고 검사와 세 데이터 변경은 같은 트랜잭션에서 처리한다.
- 수량 저장도 주문 행을 잠그고 승인 대기 상태에서만 허용한다. 수량만 저장하며 재고·원장·승인 상태는 유지한다. 재고보다 많은 수량 저장은 허용하되 승인할 때 부족을 거절한다.
- 성공 응답은 commit 뒤 반환한다. 오류 시 rollback과 세션 정리를 수행하되 커밋 장애를 저장 취소로 단정하지 않는다.
- 업무 거절 사유와 내부 장애를 구분하고 DB 예외 전문·연결값을 응답이나 로그에 노출하지 않는다.
- 조회 API는 DB의 두 주문과 현재고를 반환한다. 화면용 상태를 메모리에서 만들어 저장 결과로 보고하지 않는다.
- 자동 검사는 독자용 A·B와 분리한 주문·상품을 사용한다. 정상·부족·재승인·중간 실패·조회·HTTP 결과를 확인한다.
- 검사 프로세스 실행과 API 모듈 import를 일괄 금지하지 않는다. 설정을 내부 사용하고 비밀값을 보호하는 실행 경로로 검증한다.
- 서버를 실행해 응답을 확인하고 적용 SQL·검사 결과·남은 문제를 짧게 보고한다. 미실행 검사는 `Not Run`으로 남긴다.

- `verify_core.py`는 제공된 독립 업무 검사다. 검사에 맞추려고 기대값을 바꾸거나 검사 파일을 수정하지 않는다.
