# Chapter 8 작은 발주 검증·계산 명세

## 목적과 작업 위치

Day 16의 실제 발주 흐름을 이해하기 위한 한 품목의 Python 예제입니다.
작업 위치는 understanding/이며 공개 실행 파일은 order_example.py, 테스트는 test_order_example.py입니다.
내부 함수 이름은 고정하지 않습니다. 검증과 계산의 역할은 구분합니다.
Python 표준 라이브러리만 사용합니다. DB·API·서버·외부 의존성을 추가하지 않습니다.

## 입력 검증

- 입력은 전체 발주가 아니라 details 안의 품목 한 건입니다.
- 예시: {"prod_code": "A001", "qty": 5}.
- 상품코드는 비어 있지 않은 문자열이며 앞뒤 공백을 제거합니다.
- 수량은 bool·문자열을 제외한 양의 정수입니다. 0·음수·소수·null도 거부합니다.
- 검증 결과에는 상품코드와 수량만 남깁니다. 클라이언트의 unit_price 등 추가 필드는 복사하지 않습니다.
- 수량 0은 계산 전에 거부합니다. 공개 오류 코드나 이벤트 클래스는 요구하지 않습니다.

## 서버 기준 계산

- 검증된 품목과 서버 단가·VAT 구분을 별도로 전달받습니다.
- 예제 서버 단가는 1000원입니다. 실제 DB를 조회한 값으로 설명하지 않습니다.
- 서버 단가는 양의 정수 원 금액, VAT 구분은 문자열 "1" 또는 "2"입니다.
- 공급가액 = 서버 단가 × 수량.
- VAT "2"는 공급가액의 10%를 원 단위로 반올림하며 0.5원은 올립니다. "1"은 VAT 0원입니다.
- 합계 = 공급가액 + VAT. 반환값은 계산 결과이며 저장된 발주가 아닙니다.
- 실제 ERP는 Decimal 수량·단가를 다루며 DB 함수가 조회·계산·저장을 합니다. 예제 정수 정책과 구분합니다.

## 세 대표 사례와 완료 기준

| 사례 | 입력과 별도 서버 값 | 기대 결과 |
|---|---|---|
| 정상 | A001·수량 5, 서버 단가 1000, VAT "2" | 공급가액 5000·VAT 500·합계 5500 |
| 조작 단가 | 같은 입력에 unit_price=1 추가, 같은 서버 값 | 단가 제외·상품코드와 수량 유지, 동일한 계산 결과 |
| 수량 0 | A001·수량 0 | 검증에서 거부해 계산하지 않음 |

order_example.py를 한 번 실행하면 세 사례의 실제 결과를 표시해야 합니다.
각 테스트 함수는 입력·기대 결과를 짧은 docstring으로 설명하고 실제 단언문으로 검사합니다.
테스트 실행은 python -m unittest -v test_order_example.py입니다.
테스트 수보다 세 동작에 대한 입력·단언문·실행 근거를 확인합니다.
DB 저장·롤백·HTTP·동시성은 이 실습의 검증 범위가 아닙니다.
