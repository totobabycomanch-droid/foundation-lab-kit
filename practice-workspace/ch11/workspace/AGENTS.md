# Chapter 11 workspace 규칙

- [Chapter 11 연결 명세](../connection_spec.md)와 상위 Chapter 지침의 작업 순서를 먼저 따른다.

- backend는 `erp-project/`, frontend는 `frontend-project/`에 둔다.
- 실제 `.env` 값을 읽거나 출력하지 않는다.
- Core 기록은 DB 정상 승인·DB 중간 실패·API 정상 승인·화면 정상 승인·재고 부족의 다섯 항목이다. 각 실습 직후 같은 이름의 항목에 실제 값을 기록하며, 독자에게 설명문·코드 위치·판정 작성을 요구하지 않는다.
- 원자적 저장·요청 중 잠금·오류 처리는 구현 조건으로 유지한다. 중간 쓰기 실패의 취소는 Core의 DB 직접 호출로 확인한다. 같은 실패의 API·화면 처리와 추가 클릭 차단의 실행 검증은 심화 범위다.
- 재고 부족 뒤 같은 화면 재시도는 짧은 마무리이며 별도 필수 기록을 요구하지 않는다.
- 실행하지 않은 Supabase·브라우저 검증은 `Not Run`으로 보고한다.

- 결과를 본 뒤 업무 요청이 구현된 핵심 코드 위치와 이유를 쉽게 안내한다. 전체 코드를 다시 출력하지 않는다.
- 관찰 기록의 실제 값은 독자가 작성한다. 검토 중에는 구현이나 기록을 고치지 않는다.
- 첫 쓰기 전 거절, 중간 쓰기 실패의 취소, 동시성, 서버 중복 승인 방지를 서로 다른 검증 범위로 보고한다.
