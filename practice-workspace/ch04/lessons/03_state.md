# 실습 3 — 같은 발주를 다시 승인하면 어떻게 될까요?

실습 2의 역할 검사를 완료한 뒤 진행합니다. 본 실습을 초기화하고 A회사 관리자로 접속합니다.
1001번은 승인 대기, 승인 처리 횟수 0입니다. 초기화는 앞에서 구현한 코드를 되돌리지 않습니다.

이번 가상 회사의 확정 업무 기준은 다음과 같습니다.

> 승인 대기 발주만 승인할 수 있습니다. 승인 완료 발주를 다시 승인하면 거부하고 기존 상태를 유지합니다.

관리자라도 이미 승인한 발주에 새 승인 요청을 보내면 어떤 결과가 나와야 할지 예상해 봅니다.

## AI에게 요청하기

```text
AGENTS.md와 README.md를 읽고 현재 역할 검사와 조회·저장 흐름을 조사하세요.
변경할 파일과 이유를 알린 뒤 다음 상태 규칙을 추가하세요.

- 요청값 대신 DB에서 읽은 현재 상태로 판단하세요. 승인 대기 발주만 승인할 수 있습니다.
- 그 밖의 상태에 새 승인 요청이 오면 409와 '승인 대기 발주만 승인할 수 있습니다.'로 거부하세요.
- 거부 후 상태·처리 횟수를 유지하세요. 관리자 정상 승인, 조회 담당자 403과 회사 차단도 유지하세요.

수정 범위는 AGENTS.md의 실습 3입니다. 기존 저장 처리를 사용하세요.
요청 키·재전송 처리·재고 변경은 추가하지 않습니다. 변경 파일·실행 결과·미확인 항목을 보고하세요.
```

## 직접 확인하기

1. A회사 관리자로 발주 메뉴를 열고 1001번 상세를 선택합니다.
2. 발주 승인을 한 번 누르고 응답 200을 확인합니다.
3. 승인 완료 상태와 승인 처리 횟수 1을 확인합니다.
4. 승인 요청 직접 보내기를 눌러 같은 발주에 새 요청을 보냅니다.
5. 응답 409와 위 거부 메시지를 확인합니다.
6. 상태가 승인 완료, 처리 횟수가 1로 유지되는지 확인합니다.

직접 요청 장치는 버튼 표시와 별개로 매번 새 요청을 보냅니다. 이전 요청 키를 재사용하지 않습니다.
Ch.3에서는 같은 요청의 재전송을 다뤘습니다. 이번에는 새 요청이라도 끝난 업무를 다시 실행할 수 있는지 확인합니다.
이번 예제에서는 상태와 처리 횟수로 추가 처리가 없었는지 확인합니다.

### 선택 확인: 처음부터 승인 완료인 발주

4.3을 마친 뒤 더 확인하고 싶다면 A회사 관리자로 **1002 상세 조회**를 엽니다.
시작부터 승인 완료·처리 횟수 1인 발주입니다. **승인 요청 직접 보내기**를 눌러
`409`와 '승인 대기 발주만 승인할 수 있습니다.', 승인 완료·횟수 1 유지를 확인합니다.
이 사례는 방금 승인한 1001번뿐 아니라 기존 승인 완료 데이터에도 같은 규칙이 적용되는지 확인합니다.

## 실제 처리 흐름 따라가기

```text
AGENTS.md와 최신 코드를 읽고 상태 검사를 안내해 주세요.
발주 조회 → 역할 검사 → 현재 상태 검사 → 상태·횟수 저장 → 응답 순서로 정리하세요.
상태를 DB에서 읽는 곳과 재승인을 저장 전에 거부하는 곳을 표시하세요.
각 단계의 파일·함수·검색어를 한 줄로 적고, 찾지 못한 곳은 미확인으로 표시하세요.
코드 조사만 하고 파일 수정이나 명령 실행은 하지 마세요.
```

AI의 안내를 따라 현재 상태가 DB에서 나온 값인지, 거부가 저장 전에 일어나는지 확인합니다.
전체 SQL을 외우거나 추적 보고서를 다시 쓸 필요는 없습니다.

## AI 검증과 완료

실행 전 예상, 실제로 본 결과, 결과를 설명하는 코드 또는 업무 기준을 세 줄로 적고
아래 요청의 `[내 기록]`에 넣습니다. 실제 행동과 응답·상태·횟수를 포함하며 미확인은 그대로 적습니다.

```text
AGENTS.md를 읽고 이번 상태 규칙과 제 기록을 검증해 주세요.
현재 코드와 _starter/를 비교하고 제공 파일의 변경 여부를 검사하세요.
첫 승인 200·새 재승인 409·거부 후 상태와 횟수 유지를 확인하세요.
기존 역할 검사·조회·회사 차단도 확인하세요. 제 기록과 코드가 다르면 근거와 다음 행동을 알려 주세요.
파일 수정 없이 변경 범위·실행 결과·미확인 항목만 짧게 보고하세요.

[내 기록]
```

AI 피드백을 받은 뒤 근거 한 곳을 다시 확인하고 설명을 보완합니다.
첫 승인과 재승인의 결과를 재현하고 재전송과 재승인의 차이를 설명할 수 있으면 완료입니다.
동시 승인이나 저장 실패는 이번 직접 실행에서 시험하지 않았습니다.
