# Chapter 11 작업 규칙

## 목적과 범위

- 독자는 업무 조건을 결정하고 화면에서 정상 승인·재고 부족 결과를 판단한다.
- AI는 저장소 조사, SQL 작성·적용, API·Vue 구현, 데이터 준비, 자동 검사와 서버 실행을 맡는다.
- 먼저 [시작 안내](README.md), [연결 명세](connection_spec.md), 관련 하위 지침과 현재 파일을 읽는다.
- 구현 범위는 `workspace/erp-project/`와 `workspace/frontend-project/`다. 제공 실행 도구는 조사해 사용한다.
- Chapter 10 파일이나 참조 완성 코드를 복사하지 않는다. 다른 Chapter·Day 프로젝트는 수정하지 않는다.
- 시작 키트에는 승인 기능을 미리 완성하지 않는다. 독자의 구현 요청을 받은 뒤 생성한다.

## 한 번의 구현 요청으로 진행하기

- ch11의 명시적 기능 구현 요청에는 상위 공통 지침의 별도 조사 보고·승인 대신 조사·구현·검사·실행을 한 요청 안에서 진행하는 예외를 적용한다.
- DB·API·화면마다 독자의 다음 프롬프트나 별도 승인을 요구하지 않는다. 이미 합의된 업무 조건은 다시 묻지 않는다.
- 파일 위치·내부 함수명·Vue 변수명 같은 구현 선택은 기존 규칙과 파일을 조사해 결정한다.
- 미정 업무 조건, 명세 충돌, 범위 밖 변경이나 기존 개인 작업 덮어쓰기가 필요하면 차이와 최소 변경안을 보고하고 확인한다.
- 기존 구현과 새 명세가 다르면 자동 교체하지 않는다. 새 시작 폴더인지, 진행 중인 개인 실습인지 먼저 구분한다.
- 조사·검토만 요청받으면 수정하지 않는다. 기능 구현 요청을 다른 Chapter의 자동 작업 허용으로 확대하지 않는다.
- 실제 도구가 없거나 실행이 막혔다면 원인과 미완료 작업을 보고한다. 실행 명령이나 검사 성공을 만들어 내지 않는다.

## 로컬 설정과 DB 실행

- 이 장에서는 실행 도구·서버 프로세스가 로컬 `.env`의 연결값을 사용하는 것을 허용한다. 상위 공통 지침의 비밀값 보호는 유지한다.
- AI가 실제 `.env` 내용을 열거나 출력하지 않는다. `.env.example`과 도구의 설정 존재·연결 검사 결과로 조사한다.
- 비밀번호·DB URL을 대화로 받거나 코드·명령 인수·로그·결과 파일에 남기지 않는다.
- 독자가 설정한 폐기 가능한 ch11 전용 DB만 사용한다. 대상 확인과 표식 검사 방식은 연결 명세를 따른다.
- 전용 DB 적용 범위 안에서는 구현 요청에 포함된 SQL 적용·테스트 데이터 준비·자동 검사를 직접 수행한다.
- 예상하지 못한 기존 객체나 데이터가 있으면 삭제·초기화하지 않고 보고한다. 기존 DB를 새 명세로 자동 이전하지 않는다.
- 전체 초기화는 기본 해결책으로 삼지 않는다. 재실습 요청에서는 필요한 사례만 재준비한다.

## 검사와 독자 확인

- 자동 검사는 별도 주문·상품으로 수행하고 독자용 A·B는 시작 상태로 남긴다.
- 독자의 Core 직접 확인은 정상 승인 A와 재고 부족 B다. DB·API별 승인 반복이나 중간 실패 실험을 필수로 추가하지 않는다.
- 트랜잭션·재승인 방지는 구현 조건이다. 중간 실패·동시성·응답 유실의 별도 실험은 선택 범위로 구분한다.
- 오류를 조사할 때 실제 코드·실행 결과·DB 상태를 사용한다. 독자에게 도구 사이로 전체 로그를 옮기게 하지 않는다.
- 수정 후 관련 검사를 다시 실행하고, 독자가 문제가 있던 사례를 다시 확인할 수 있게 준비한다.
- `observation_record.md`의 직접 관찰값은 독자만 작성한다. 기존 다섯 실험 양식을 추가 필수 과제로 요구하지 않는다.
- 실행 결과는 `Pass`, `Fail`, `Not Run`, `테스트 없음`으로 구분한다. 구현 존재·자동 검사·독자 화면 확인을 서로 대신하지 않는다.

## 짧은 완료 보고

- 구현 결과, DB 적용 결과, 검사 결과, 실제 실행 중인 화면 주소, 남은 문제를 짧게 보고한다.
- 테스트 데이터와 독자용 A·B가 분리됐는지 확인한다. 미실행 항목은 명시한다.
- 코드 설명 요청에는 실제 파일 위치와 핵심 코드만 사용해 요청 전송·조건 검사와 저장·저장 후 재조회를 설명한다.
- 상위 공통 지침의 긴 근거표와 변경 파일 전체 독해를 화면 테스트의 선행 과제로 요구하지 않는다. 상세 근거는 필요할 때 제시한다.

- `verify_core.py`는 제공된 독립 업무 검사다. 검사에 맞추려고 기대값을 바꾸거나 검사 파일을 수정하지 않는다.
