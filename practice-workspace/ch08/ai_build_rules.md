독자가 지정한 폴더의 AGENTS.md, README.md, project/AGENTS.md와 기존 코드·모델을 조사하세요.
chapter8_order_spec.md에서 현재 단계의 업무 조건·완료 기준과 필요한 앞 단계의 구조를 확인하세요.
공개 이름·파일 위치·자료형·단계 연결 규약을 유지하세요. 테스트는 해당 구현 루트에서 실행하세요.
파일이 없으면 대상의 절대 경로와 앞 단계의 작업 경로를 대조하고, 임의로 재생성·초기화하지 마세요.
reference/를 답안으로 읽거나 복사하지 말고, .env와 비밀 값은 읽거나 출력하지 마세요.
변경·보존 파일, 업무 규칙과 확인 명령을 짧게 보고하고 승인 전에는 수정하지 마세요.
기존 구현이 요청 조건을 충족하면 재작성 없이 검증하고 변경이 필요 없다고 보고하세요.
승인 후 현재 단계만 최소 변경하고 이전 결과·시작 파일·후속 단계는 보존하세요.
규약 충돌이나 승인한 계획의 변경이 필요하면 적용 전에 이유와 최소 변경안을 보고하세요.
공개 클래스의 역할·필드와 함수의 입력·반환값·예외를 짧은 docstring으로 설명하세요.
저장 함수의 세션·트랜잭션 사용 조건도 조사해 설명하되 후속 단계의 연결을 미리 구현하지 마세요.
이유가 필요한 판단에만 짧은 주석을 작성하세요.
현재 단계의 테스트는 chapter8_order_spec.md의 필수 검사에 맞추고 이전 단계 테스트도 보존·실행하세요.
구현 후 ai_review_rules.md의 근거·판정 기준으로 실제 입력과 단언문을 확인하고 테스트를 실행하세요.
완료 보고는 변경 파일, 실제 실행 명령과 마지막 요약, 필수 검사의 판정, 대표 사례 하나로 정리하세요.
대표 사례는 실제 테스트의 짧은 코드와 파일 경로·검색할 이름을 제시하고 입력·결과를 쉽게 설명하세요.
테스트 후 파일이 바뀌면 최신 파일로 재실행하세요. 실패·미실행·누락은 완료로 보고하지 마세요.
