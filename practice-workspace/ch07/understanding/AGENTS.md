## 조사와 작업 범위

- 먼저 README.md를 읽고 현재 폴더의 절대 경로와 기존 생성 파일을 확인한다.
- 변경 범위를 짧게 보고한다. 계획만 요청받았으면 멈추고, 승인된 범위는 이어서 진행한다.
- 이 폴더에 transaction_example.py, sale_example.py, test_examples.py만 생성·수정한다.
- 함수 이름은 자유롭게 정하되 README의 실행 파일명과 필수 검사 조건을 지킨다.
- reference/를 답안으로 읽거나 복사하지 않는다. legacy-api/와 다른 Chapter를 수정하지 않는다.
- .env·비밀 값은 읽거나 출력하지 않는다.

## 구현과 근거

- Python 표준 라이브러리만 사용한다. SQLite DB는 각 독립 사례·테스트의 메모리에 만들고 닫는다.
- 함수와 테스트의 docstring에 입력과 검사 결과를 짧게 설명한다.
- README의 필수 검사를 실행하고 출력값이 실제 DB 조회값임을 확인한다.
- 실행 명령·결과·절대 작업 경로를 보고한다. 근거 경로는 ch07/부터 표시한다.
- Pass·Fail·Not Run·테스트 없음을 구분한다. 테스트 이름은 최신 파일에서 직접 확인한다.
- 순차 재시도와 의도적 예외 롤백을 실제 동시 요청·서버 강제 종료·HTTP 검증으로 보고하지 않는다.
