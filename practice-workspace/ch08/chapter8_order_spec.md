# Chapter 8 작은 발주 검증·계산 명세

## 목적과 작업 위치

Day 16의 실제 발주 흐름을 이해하기 위한 한 품목의 Python 예제입니다.
작업 위치는 understanding/이며 공개 실행 파일은 order_example.py, 테스트는 test_order_example.py입니다.
공개 함수는 아래 규격으로 맞추고 내부 함수 이름과 구현 방법은 자유롭게 정합니다.
Python 표준 라이브러리만 사용합니다. DB·API·서버·외부 의존성을 추가하지 않습니다.

## 직접 호출과 고정 검사의 공개 규격

- validate_item(payload)는 품목 객체를 받아 prod_code·qty만 있는 dict를 반환합니다.
- calculate_amounts(item, *, server_unit_price, is_vat)는 검증된 품목과 별도 서버 값을 받습니다.
- 계산 결과는 unit_price·supply_amount·vat_amount·total_amount만 있는 dict입니다.
- 잘못된 입력·서버 단가·VAT 구분은 ValueError로 거부합니다.
- 모듈을 import할 때 대표 사례를 자동 실행하지 않습니다. 직접 호출과 스크립트 실행을 구분합니다.
- understanding/checks/test_order_rules.py는 업무 규칙에서 정한 고정 검사입니다. 읽되 수정하지 않습니다.
- reference/는 생성·검증의 답안으로 읽거나 복사하지 않습니다.

## 입력 검증

- 입력은 전체 발주가 아니라 details 안의 품목 한 건입니다.
- 예시: {"prod_code": "A001", "qty": 5}.
- 상품코드는 비어 있지 않은 문자열이며 앞뒤 공백을 제거합니다.
- 수량은 bool·문자열을 제외한 양의 정수입니다. 0·음수·소수·null도 거부합니다.
- 검증 결과에는 상품코드와 수량만 남깁니다. 클라이언트의 unit_price 등 추가 필드는 복사하지 않습니다.
- 수량 0은 계산 전에 거부합니다. 공개 오류 코드나 이벤트 클래스는 요구하지 않습니다.

## 서버 기준 계산

- 검증된 품목과 서버 단가·VAT 구분을 별도로 전달받습니다.
- 예제 서버 단가는 1000원입니다. 실제 DB를 조회한 값으로 설명하지 않습니다.
- 서버 단가는 양의 정수 원 금액, VAT 구분은 문자열 "1" 또는 "2"입니다.
- 공급가액 = 서버 단가 × 수량.
- VAT "2"는 공급가액의 10%를 원 단위로 반올림하며 0.5원은 올립니다. "1"은 VAT 0원입니다.
- 합계 = 공급가액 + VAT. 반환값은 계산 결과이며 저장된 발주가 아닙니다.
- 실제 ERP는 Decimal 수량·단가를 다루며 DB 함수가 조회·계산·저장을 합니다. 예제 정수 정책과 구분합니다.

## 세 대표 사례와 완료 기준

| 사례 | 입력과 별도 서버 값 | 기대 결과 |
|---|---|---|
| 정상 | A001·수량 5, 서버 단가 1000, VAT "2" | 공급가액 5000·VAT 500·합계 5500 |
| 조작 단가 | 같은 입력에 unit_price=1 추가, 같은 서버 값 | 단가 제외·상품코드와 수량 유지, 동일한 계산 결과 |
| 수량 0 | A001·수량 0 | 검증에서 거부해 계산하지 않음 |

order_example.py를 한 번 실행하면 세 사례의 실제 결과를 표시해야 합니다.
사례명·표시 라벨·입력 오류 설명은 한국어로 작성하며 함수명·반환 필드·ValueError는 공개 규격을 유지합니다.
정상·조작 단가 요청은 원본을 '입력', 실제 검증 반환값을 '검증된 품목', 실제 계산 반환값을 '계산 결과'로 구분합니다.
검증된 품목은 prod_code·qty만 담고, 계산 결과의 unit_price는 서버 단가임을 구분할 수 있어야 합니다.
수량 0은 입력과 '계산 전 거부'·실제 오류 설명을 표시합니다. 검증 실패를 성공한 검증·계산 결과처럼 표시하지 않습니다.
각 테스트 함수는 입력·기대 결과를 짧은 docstring으로 설명하고 실제 단언문으로 검사합니다.
테스트 실행은 python -m unittest -v test_order_example.py입니다.
테스트 수보다 세 동작에 대한 입력·단언문·실행 근거를 확인합니다.
공백 제거, 논리값·문자열·0·음수·소수·null 수량 거부와 VAT "1"의 0원도 테스트합니다.
수량 1·VAT "2"에서 서버 단가 104·105·106원의 VAT는 각각 10·11·11원이며 합계는 114·116·117원입니다.
서버 단가의 양의 정수 조건과 VAT 구분 "1"·"2" 외 값의 거부도 테스트합니다.
understanding/에서 ../../../tools/verify_ch08_core.ps1로 생성 테스트와 고정 검사를 함께 실행합니다.
고정 검사는 생성 테스트의 기대값을 가져오지 않습니다. 코드의 계산 전 거부 순서와 대표 테스트의 단언문은 별도로 읽습니다.
DB 저장·롤백·HTTP·동시성은 이 실습의 검증 범위가 아닙니다.

## 터미널에서 직접 입력하는 모드

- python order_example.py --interactive는 상품코드·수량·요청 단가를 차례로 입력받습니다.
- 인자 없는 실행은 기존 세 대표 사례만 출력하며 입력을 기다리지 않습니다. import도 입력을 요구하지 않습니다.
- 터미널 입력은 문자열이므로 수량·요청 단가를 정수로 변환한 뒤 요청 객체를 만듭니다. 숫자 5를 입력하는 것과 validate_item에 문자열 "5"를 직접 넘기는 것은 다른 경로입니다.
- 정수 변환 실패는 한국어 입력 오류로 표시하고 계산하지 않습니다. 수량 0·음수는 기존 validate_item의 ValueError로 거부합니다.
- 서버 단가 1000원·VAT "2"는 고정합니다. 입력받은 요청 단가는 검증 결과에서 제외하고 서버 단가를 덮어쓰지 않습니다.
- 성공 시 입력·검증된 품목·계산 결과를 구분하고 적용한 서버 단가·공급가액·VAT·합계를 한국어 라벨로 보여 줍니다.
- 실패 시 오류 설명만 표시하고 성공한 검증·계산 결과를 만들지 않습니다.
- 성공·실패 뒤 '다시 입력하시겠습니까? (y/n):'를 묻습니다. y는 새 입력부터 시작하고 n은 종료합니다. 이전 시도의 품목·계산 결과를 재사용하지 않습니다.
- 수량 5·요청 단가 100원 및 10원 모두 5000·500·5500원, 수량 -3·0 거부, 소수·문자 입력의 변환 오류, 거부 뒤 정상 재입력과 종료를 테스트합니다.
- 자동 테스트는 입력을 미리 제공해 대기하지 않게 합니다. 기존 고정 검사는 공개 검증·계산 함수를 검사하며 직접 입력 흐름의 검사를 대신하지 않습니다.
