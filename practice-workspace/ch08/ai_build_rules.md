## 변경 전후 비교

- 변경 전에 허용된 실습 범위의 파일 목록과 기존 두 생성 파일의 내용을 확인하세요. 파일이 없으면 새로 생성할 파일임을 구분하고, 기존 변경을 덮어쓰거나 되돌리지 마세요.
- Git을 사용할 수 있으면 작업 전 상태·차이를 확인하고, 이번 작업 직전 내용과 작업 후 내용을 비교하세요. 작업 후 git status --short나 HEAD 대비 diff만으로 기존 변경을 이번 AI 변경이라고 보고하지 마세요.
- 새 파일과 미추적 파일은 내용을 직접 읽으세요. 기본 git diff에 나타나지 않는 내용도 비교 대상에 포함하세요.
- Git이 없는 ZIP 폴더에서는 변경 전 파일 목록·내용과 비교 가능한 기준을 확보하세요. 확인한 내용을 AI 작업 맥락에서 활용하되, 실습 폴더에 별도 백업·보고서 파일을 만들거나 독자에게 Git 초기화·커밋·기록 제출을 요구하지 마세요.
- 읽기 전용 고정 검사와 지침은 작업 전후 내용 또는 해시로 대조하세요. 기준을 확보하지 못했거나 새 대화에서 확인할 수 없다면 추정하지 말고 비교하지 못한 범위를 보고하세요.
- 합의된 두 파일의 범위 안에서는 이어서 진행하세요. 다른 파일 변경이나 업무 규칙·기대값 변경이 필요하면 적용 전에 파일과 이유를 보고하고 확인을 받으세요.
