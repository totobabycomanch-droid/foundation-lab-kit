# Chapter 3 예상 최종 판정

이 파일은 AI A와 AI B가 독립 판정을 완료한 뒤 비교 단계에서만 읽는다.
아래 판정은 실행 범위에 따라 적용한다. 테스트 없음과 미실행은 구현 실패의 근거가 아니다.

| 검토 항목 | 예상 판정 | 핵심 근거 |
|---|---|---|
| 본사 사용자 권한과 요청 주체·대상 회사의 분리 | 실행한 테스트가 확인한 범위만 `Pass(조건부)` | 요청 주체와 등록 대상은 분리된다. 미실행 조건은 `Not Run`이며 실제 인증은 스텁이므로 보장 범위 밖이다. |
| 같은 화면의 연속 클릭 방지 | 해당 E2E 통과 시 `Pass(제한적)`, 미실행 시 `Not Run` | `isSaving`은 같은 화면 인스턴스의 재진입만 막는다. 구현 확인과 실행 검증을 분리한다. |
| 네트워크 재전송 식별 | `Fail` | 회사 등록 POST는 멱등 키를 보내거나 검사하지 않는다. |
| 같은 `corp_id`의 중복 행 방지 | 제약 선언은 구현 확인, 실제 DB 미검증 시 동작 검증은 `Not Run` | DDL에 `UNIQUE`가 있다. 테스트 부재만으로 구현을 `Fail`로 판정하지 않는다. 이전 성공 응답 재사용과 실제 DB 충돌 응답은 별개다. |
| 가맹점·부서·관리자 사원의 원자 저장 | `Fail` | 개별 저장하며 하위 저장 예외를 삼키고 성공을 반환할 수 있다. |
| 재전송·동시 요청·하위 저장 실패 테스트 | 검증 부재, 실행 결과는 `Not Run(테스트 없음)` | 현재 자동 테스트에 해당 실패 시나리오가 없다. 테스트 상태는 `테스트 없음`으로 기록하며 구현 실패와 구분한다. |
